一、项目定位

项目名称：EnArrower。

这是一个轻松解压、带适度顺序推理的箭头解谜游戏。玩家点击箭头，让它沿朝向离开棋盘；部分箭头离场后改变闸门状态，因此需要安排顺序。

核心体验：
观察棋盘 → 选择箭头 → 箭头滑出 → 机关变化 → 继续疏通 → 清空通关。

不设置强制倒计时、生命值或扣分。允许试错，提供无限撤销、重开和提示。

交付形式：
- 可在电脑和手机浏览器中使用的单机网页。
- 支持鼠标、触摸和基本键盘操作。
- 本地存档，无登录、数据库或跨设备同步。
- 游戏运行本身不依赖 AI API。
- 界面、关卡和素材自行设计，不复制其他游戏。

二、技术方案

没有现有技术约束时，默认采用：
- Vite + TypeScript。
- SVG 绘制棋盘与箭头。
- CSS 或浏览器原生动画能力实现动效。
- localStorage 保存进度。
- 合适的规则单元测试和浏览器流程测试工具。

如果现有项目使用其他合理技术栈，优先复用，不为统一技术而重写。

将规则与界面分离，建议至少区分：
规则和游戏状态、关卡数据、关卡校验、求解器、渲染与动画、存档、界面、测试和开发文档。

规则使用网格坐标，不以 DOM 或像素位置作为游戏状态来源。选择兼容依赖并提交锁文件，记录实际运行环境，不凭空指定已安装版本。

三、棋盘和箭头规则

1. 棋盘为矩形网格，第一版宽 5～7 格、高 3～7 格。
2. 每关 3～12 支箭头。
3. 箭头是连续占据 1～3 格的直线，方向为上、下、左、右。
4. 数据明确记录头部坐标、方向、长度和可选的机关组 ID。
5. 箭身与朝向共线，从头部向反方向推导占用格。
6. 初始箭头之间、箭头与闸门之间不能重叠，所有占用格不能越界。
7. 点击头部或箭身均选中同一支箭头。
8. 箭头只能沿自身朝向整体平移离场，不能转向、拖动或中途停靠。
9. 移动前检查整支箭头完全离场所需经过的路径。
10. 其他剩余箭头和关闭的闸门构成阻挡；自身原占用格不算障碍；开启的闸门可以通过。
11. 被阻挡时保持原位，并突出实际阻挡物，不扣分、不改变机关、不增加撤销历史。
12. 所有箭头离场即通关，闸门不用清除。

四、开关与闸门

第一版只做一种机关：开关箭头成功离场后，切换关联组内所有闸门的状态。

具体要求：
- 每支开关箭头只属于一个机关组。
- 同组可以有多支开关箭头。
- 每组共享一个开关状态。
- 每关最多两组机关，合计最多四个闸门格。
- 用不同符号（如 ◇、○）加颜色区分组别，不能只依赖颜色。
- 普通箭头离场不改变闸门。
- 被阻挡、查看提示、预览机关都不能触发切换。
- 先依据移动前的门状态判断是否能离场，成功离场后才切换。
- 不能先打开自己控制的门，再允许自己穿过去。
- 最后一支箭头离场后，即使关闭了门，也应正常通关。

提供机关预览：
- 电脑悬停或键盘聚焦开关箭头时，突出关联闸门，说明离场后开启还是关闭。
- 手机提供“查看机关”模式，在该模式下点击只预览、不移动；退出后恢复普通操作。

五、箭头离场动画

这是必须完成的核心功能。

1. 整支箭头沿朝向连续滑动，直到尾部完全离开棋盘后才移除。
2. 不能用原地淡出或瞬间消失代替移动。
3. 普通动画时长建议 250～450ms，按实际手感调整。
4. 动画要流畅，箭头不能穿过原本阻挡它的物体。
5. 一次只执行一个动作。动画期间禁用重复移动、撤销、重开、切关和提示。
6. 状态处理顺序：
   校验路径 → 保存动作前快照 → 播放动画 →
   一次性提交箭头移除和机关切换 →
   保存稳定状态 → 判定通关 → 释放输入锁。
7. 动画完成逻辑只能执行一次。
8. 处理取消、窗口尺寸变化和减少动态效果等情况，不能重复切换机关或永久锁死。
9. 尊重 prefers-reduced-motion；缩短或跳过动画时，规则结果保持一致。
10. 最后一支箭头完成动画后，才显示通关反馈。

六、撤销、重开和提示

撤销：
- 无限次撤销。
- 恢复最近一次成功移动前的完整状态，包括箭头、闸门及关卡运行状态。
- 没有历史时禁用按钮。
- 被阻挡的操作不进入历史。
- 通关后可撤销最后一步，但不收回已经获得的解锁记录。

重开：
- 恢复本关初始布局和初始闸门状态。
- 清空本关撤销历史。
- 保留已完成和已解锁记录。

提示：
- 必须根据当前状态搜索完整解法。
- 突出一支“执行后仍然可以通关”的箭头，不自动移动。
- 不能把“当前可移动”直接当作“正确下一步”。
- 当前状态无解时，即使仍有局部可移动箭头，也应提示撤销或重开。
- 求解器只需覆盖第一版规模，可使用记忆化搜索，避免无必要的复杂系统。

七、存档

使用 localStorage 保存：
- 已完成和已解锁关卡。
- 当前关卡。
- 当前稳定棋盘状态。
- 当前关卡撤销历史。

要求：
- 设置存档版本并校验数据。
- 只保存已经完成的动作，不保存动画坐标、输入锁和待执行回调。
- 动画中刷新后恢复上一个稳定状态。
- 损坏、过期、关卡不匹配或存储不可用时安全处理并提示，不能白屏。
- 存储写入失败时游戏仍可继续，但说明进度可能无法保存。
- README 明确说明存档仅限同一浏览器、同一站点来源。

八、关卡内容

制作 12 个原创固定关卡：
- 1～3：普通箭头、方向和阻挡。
- 4～6：一组机关，以开门为主。
- 7～9：关门前的顺序判断。
- 10～12：最多两组机关组合。

每关只安排一两个关键判断，避免大量机关堆叠。允许多种正确顺序，不强求唯一解。

每关必须：
- 有稳定 ID 和简短设计目标。
- 通过坐标、长度、方向、重叠和机关引用校验。
- 至少有一条完整解法。
- 使用实际规则引擎逐步重放解法，确认每步合法且最终清空。

不要随机摆出关卡后直接宣称有解。自动验证之后，列出需要人工试玩检查的节奏问题。

先使用以下固定样例建立最小可玩版本：
棋盘宽 5、高 3，左上角为 (0,0)。
A：头部 (0,0)，向右，长度 1，控制 diamond 组。
B：头部 (0,2)，向右，长度 1，普通箭头。
C：头部 (2,2)，向上，长度 1，普通箭头。
diamond 闸门位于 (3,2)，初始开启。

预期：
- 初始 B 被 C 阻挡。
- C → B → A 可以通关。
- 先 A 会关门，当前状态不再有完整解法。
- A → C 后，B 被闸门阻挡。
- 撤销正确恢复箭头和闸门。

视觉要求：
