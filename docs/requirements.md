## 1. 定位
轻松解压、带适度顺序推理的箭头解谜单机网页游戏。核心循环：观察棋盘 → 选择箭头 → 箭头滑出 →
机关变化 → 继续疏通 → 清空通关。无强制倒计时、生命值、扣分；允许试错，提供无限撤销、重开、提示。
电脑 + 手机浏览器，鼠标 / 触摸 / 基本键盘；localStorage 本地存档；运行不依赖 AI API。

## 2. 核心规则（摘要）
- 矩形网格宽 5~7、高 3~7；每关 3~12 支直线箭头，占连续 1~3 格，方向上/下/左/右。
  （第二轮 §9 起：宽 5~10、高 3~14，并允许折线 / 可调头 / 接力形态。）
- 数据记录头部坐标、方向、长度、可选机关组；箭身从头部沿朝向反方向推导。
- 初始箭头之间、箭头与闸门不重叠、不越界；点头部或箭身选中同一支。
- 只能沿朝向整体平移离场；移动前检查完全离场路径；其他箭头与关闭闸门阻挡，自身原占用格不算障碍，开启闸门可通过。
- 被阻挡保持原位、突出阻挡物，不扣分、不改机关、不进撤销历史。
- 开关箭头成功离场后切换同组所有闸门一次；每支开关只属一组；每关最多两组、合计最多 4 闸门格；
  用符号（◇/○）加颜色区分；先按移动前门状态校验，成功离场后才切换；不能靠自己的门穿过原本关闭的门。
- 所有箭头离场即通关，闸门不用清除；最后一支离场后即使关门也通关。
- 机关预览：电脑悬停 / 键盘聚焦开关突出关联闸门并说明将开启/关闭；手机“查看机关”模式点击只预览不移动。

## 3. 离场动画（必做）
整支沿朝向连续滑动到尾部完全出界才移除；普通 250~450ms；动画期间禁用重复移动/撤销/重开/切关/提示；
顺序：校验 → 存快照 → 动画 → 一次性提交移除+切换 → 存稳定存档 → 判通关 → 释放锁；完成逻辑只执行一次；
处理取消、尺寸变化、减少动态；动画中刷新恢复上一稳定状态；最后一支动画完成后才显示通关。

## 4. 辅助与存档
无限撤销（恢复箭头+闸门+运行状态，空历史禁用，被阻挡不进历史，通关后可撤销但不收回解锁）；
重开恢复初始布局+门状态+空历史，保留完成/解锁；提示基于当前状态搜索完整解法，突出“执行后仍可通关”的箭头，
无解时即使有局部可移动也提示撤销/重开；localStorage 存完成/解锁/当前关卡/稳定状态/撤销历史，带版本与校验，
坏档/过期/不匹配/存储不可用安全回退不白屏，写入失败仍可玩但提示。

## 5. 关卡
12 个原创固定关卡：1~3 普通；4~6 一组开门；7~9 关门前顺序；10~12 两组组合。每关稳定 ID + 设计目标 +
校验 + 至少一条引擎重放解法。固定回归样例（宽5高3：A(0,0)右◇、B(0,2)右、C(2,2)上、◇门(3,2)初开）用于测试夹具。
追加（2026-11-16 用户指令「再多创建机关关卡」）：新增 l13~l18 六个机关关（13~15 单组进阶、16~18 双组进阶），
总数 18；基线 12 关梯度与规则不变，新增关同样经校验 + 引擎重放。见 decisions.md D11。

## 6. 界面
入口（名称/开始继续/选关/玩法说明）、游戏（关卡名/棋盘/撤销/重开/提示/查看机关/返回）、通关（反馈/下一关/重玩/返回）、
选关（已完成/已解锁/未解锁）。简洁柔和、棋盘为视觉中心；手机触摸目标约 44px；适配 360/390/桌面；控件可访问名称 +
键盘聚焦触发 + 动态结果可访问通知。

## 9. 第二轮玩法扩展（2026-11-24 用户指令，覆盖基线相应条目）
来源：用户本轮七节指令（检查现有代码、复用架构、不重写）。基线 §2 的网格/箭头形态上限以本节为准。
1. **扩大地图**：中后段大棋盘面积约旧关 2 倍（7×7=49 → 8×12=96）；手机格子仍 ≥44px，不靠缩小 UI 达成。
   校验上限放宽为宽 5~10、高 3~14、箭头 3~12。
2. **折线箭头**：L 形（≤1 处直角弯、2~5 格）；绳随路线离场（头先出、弯折依次跟出）；
   碰撞 / 预览 / 动画 / 点灯共用同一条路线（自身格 + 出口射线）。
3. **可调头箭头 ⇄**：仅直箭头、不与开关徽记共存；点击只选中，「调头」180° 翻转与「发射」是两个显式操作，
   各占一步可撤销；刷新恢复朝向；必须有真正依赖调头才可解的关卡（l21/l22）。
4. **接力箭头**：A 领头 / B 跟随，虚线连接；点 B 只高亮 A；启动前预演两支，任一被挡整队原地不动、不进历史；
   成功时顺序动画、一次性提交、一次撤销完整恢复（含闸门）；教学关 l23「接力过桥」。
5. **护送关 ★**：送出 ★ 即通关，其余箭头可留场；提示按护送目标识别胜负（l25）。
   **可选点灯**：箭头离场路线经过灯格即点亮；通关时全亮给「点亮小屋」庆祝，缺灯仍通关；
   灯状态随撤销 / 存档恢复；灯 + 调头组合关 l26、终局 l27。
6. **提示 / 求解 / 存档 / 测试**：提示给出具体操作（点名开关 / 调头 / 接力）；求解器记录访问状态数，
   状态键含朝向 + 剩余 + 闸门（调头循环不死循环）；旧存档兼容（turned/lit 缺省 []）；每关引擎重放；
   记录求解实测耗时；重点验证折线动画中途、调头阻挡、接力失败不变、接力单撤销、护送与点灯胜负；
   桌面 + ≥1 手机宽度实玩；新旧截图与动画采样；未执行一律「未验证」。
7. **交付顺序**：大棋盘与折线 → 可调头 → 接力 → 特殊关卡目标，每阶段留下可玩关卡。
   本轮只记录需求变化、实际修改与测试结果；最终报告与整体收尾待游戏内容定稿后再做。

## 10. 第三轮修改（2026-11-25 用户指令，覆盖基线相应条目）
来源：用户本轮三条指令。基线 §2 的长度/弯折上限与 §9.3 的调头操作入口以本节为准。
1. **调头入口改到箭上**：⇄ 箭头尾部徽记即调头按钮，直接点击原地翻转 180°，不再经过下方按钮；
   底部选中条只保留「发射 / 取消」；点箭身仍为选中。徽记命中区独占尾格（≥44px 触摸目标），
   键盘可聚焦徽记回车调头。
2. **棋盘铺满 / 加密**：无机关无灯关（l01/l02/l03/l19）箭头必须铺满全部格子（49/49）；
   有门/灯关尽量添加箭头加密（不要求铺满），填充箭不得破坏原有教学解法与机关时序。
   校验脚本对无机关无灯关强制覆盖率 = 宽×高。
3. **更长更多弯折**：直箭身长度上限 3 → 5；折线箭身 2~5 格 → 2~9 格、直角弯 ≤1 → ≤3；
   ⇄ 仅直箭头且 len≥2（徽记独占尾格）。其余规则（绳随路线、碰撞、点灯、接力、护送）不变。
本轮仍只记录需求变化、实际修改与测试结果；最终报告与整体收尾待游戏内容定稿后再做。

## 11. 第四轮修改（2026-11-25 用户指令：Windows 桌面应用）
来源：用户本轮单条指令「把这个做成一个可以下载到电脑上玩的应用程序，只支持windows」。
1. **交付形态**：Electron 打包的 Windows 免安装单 exe（portable 目标），下载后双击即玩；
   仅出 Windows 目标，不做 macOS/Linux。网页版保留且规则/关卡与第三轮完全一致。
2. **同一份构建**：vite `base:'./'` 使 dist 同时兼容 http 预览与 Electron 加载；不另维护桌面分支代码。
   实施说明：`file://` 下 ES module 会被 CORS 拦截，故渲染进程改用自定义标准协议 `app://` 加载同一份 dist。
3. **存档位置**：桌面版 localStorage 落在 Electron 应用 userData 目录，与浏览器存档相互独立；
   schemaVersion/校验/回退逻辑不变。
4. **安全边界**：渲染进程 contextIsolation + sandbox、无 nodeIntegration、无 preload；游戏本身零网络请求。
5. 本轮仍只记录需求变化、实际修改与测试结果；最终报告与整体收尾待游戏内容定稿后再做。
